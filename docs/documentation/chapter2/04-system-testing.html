Chapter II · Part D

System Testing and Implementation

This section describes the evaluation methodology used to verify the Knowing Eye platform against its functional requirements, non-functional quality attributes, AI classification performance, and end-user acceptance. It follows the Methods portion of the IMRAD structure: research design, instruments, procedures, metrics, and analysis plan. Quantitative outcomes and interpretation are reserved for the Results and Discussion chapter.

Evaluation Framework

System testing addresses Specific Objective 7—to evaluate functionality, usability, and effectiveness in improving examination monitoring. The evaluation adopts a mixed-methods design combining (1) layered software verification, (2) controlled AI benchmark testing, and (3) structured user-acceptance assessment.

Evaluation strandPrimary questionMethodOutput type
Functional verificationDoes each module behave as specified?Automated API tests, integration flows, IEEE UAT scenariosPass/fail per test case; defect log
AI classification performanceHow accurately does the pipeline classify examinee sessions as compliant or non-compliant?Held-out labeled sessions; behavior-average thresholdingAccuracy, precision, recall, F1-score
User acceptanceDo administrators and examinees find the system usable and acceptable?UTAUT survey after mock-examination sessionsConstruct means, intention scores

Participants

User acceptance testing and the UTAUT survey involve representatives from Legacy College of Compostela — Institute of Information Technology:

  • Administrators / proctors — conduct mock exam setup, live monitoring, and report review.
  • Examinees — complete a timed mock examination under webcam monitoring.

Participants are briefed on the study purpose, data handling (session-scoped behavior logs, no public media exposure), and voluntary participation before UAT begins. Mock examinations simulate realistic duration, question types, and monitoring load without affecting live institutional records.

AI Behavioral Classification Evaluation

Classification performance is measured on a held-out labeled dataset of mock-examination monitoring sessions. Each session comprises frame-level recordings annotated by expert reviewers for target behavioral events (e.g., face absence, identity mismatch, abnormal head pose, suspicious posture). Sessions are also assigned an overall ground-truth label—compliant (negative) or non-compliant (positive)—based on whether the examinee exhibited suspicious behavior during the session. The dataset combines controlled mock-examination recordings and curated public samples, split into training (excluded from this evaluation), validation, and test partitions. Status as of Capstone 2 planning: this collection has not yet been executed - see Part C, Dataset Methodology for why (MediaPipe and ArcFace run as frozen pre-trained models here, so the "training" partition is reserved for future fine-tuning rather than in active use), and for the split ratio stated and justified ahead of collection. The numeric results this section's framework will produce belong in the Results and Discussion chapter once the deployment-window mock sessions described in Part E have run.

Threshold-Based Binary Classification

Because the Knowing Eye pipeline produces continuous compliance scores rather than a single trained classifier output, binary predictions for metric computation use a behavior average compared against the pipeline's configured alert threshold. This mirrors the same threshold logic applied during live monitoring (alert_threshold_pct in backend/ai/config/pipeline.yaml).

TermOperational definition
Behavior averageArithmetic mean of overall_compliance_pct across all processed frames in an examinee's monitoring session. overall_compliance_pct is the weighted aggregate of face presence, gaze focus, posture, and identity metrics produced by behavior/scoring.py.
Classification thresholdalert_threshold_pct from the AI pipeline configuration (default 80%). The same value triggers per-metric alerts during live sessions.
Positive classNon-compliant / suspicious session — behavior average below the classification threshold.
Negative classCompliant session — behavior average at or above the classification threshold.
Ground truthExpert-assigned session label: compliant (negative) or non-compliant (positive), derived from frame-level annotations and proctoring review.

For each examinee session in the held-out test partition, the pipeline processes all labeled frames, computes the behavior average, and applies the threshold to produce a single predicted class. Predicted and ground-truth labels are then compared to populate the confusion matrix.

Confusion Matrix and Operational Definitions

OutcomeGround truthPredictionMeaning

MetricDefinitionFormula
AccuracyProportion of all session predictions that are correct(TP + TN) / (TP + TN + FP + FN)
PrecisionProportion of positive predictions that are true positivesTP / (TP + FP)
RecallProportion of actual positives correctly identified (sensitivity)TP / (TP + FN)
F1-scoreHarmonic mean of precision and recall2 × (Precision × Recall) / (Precision + Recall)

Success Criteria

Prior to test execution, the following minimum acceptable thresholds are established based on proctoring literature and institutional reliability requirements. Meeting or exceeding these values on the held-out test set constitutes acceptable classification performance.

MetricMinimum acceptable valueRationale
Accuracy≥ 90%Overall correctness across balanced compliant and non-compliant sessions
Recall≥ 88%Sufficient sensitivity to true violations during live monitoring
Precision≥ 88%Limits false alarms that burden administrators
F1-score≥ 88%Balanced trade-off between precision and recall

Usability and Acceptance Evaluation (UTAUT)

End-user acceptance is assessed with the Unified Theory of Acceptance and Use of Technology (UTAUT) survey instrument adapted for webcam-monitored online examinations. After completing a mock examination or monitoring session, each participant responds to 25 Likert-scale items (1 = strongly disagree, 5 = strongly agree) grouped into five constructs:

ConstructItemsWhat it measures
Performance Expectancy (PE)1–5Perceived improvement in monitoring efficiency and exam integrity
Effort Expectancy (EE)6–10Ease of learning and operating the platform
Social Influence (SI)11–15Institutional encouragement and peer norms
Facilitating Conditions (FC)16–20Availability of resources, training, and technical support
Behavioral Intention (BI)21–25Willingness to adopt Knowing Eye in future examinations

Construct scores are computed as the arithmetic mean of item responses within each construct. Higher means indicate stronger acceptance. Open-ended feedback is collected optionally to supplement quantitative scores.

Data Collection and Analysis Plan

Data from all evaluation strands are consolidated into structured result records (docs/testing/testing(IEEE)/results-data/ and UTAUT results-data/). Analysis proceeds as follows:

  1. Functional tests — Compute pass rate per module and overall; map each result to a functional requirement ID in the traceability matrix.
  2. AI metrics — For each examinee session in the held-out test partition, compute the behavior average (mean(overall_compliance_pct)), apply the classification threshold (alert_threshold_pct), and compare predicted vs. expert ground-truth labels to build a session-level confusion matrix; derive accuracy, precision, recall, and F1-score; compare against success criteria.
  3. UTAUT — Compute descriptive statistics (mean, standard deviation) per construct; compare administrator vs. examinee subgroups where sample size permits.
  4. Triangulation — Relate functional pass/fail outcomes, classification performance, and acceptance scores to Specific Objective 7 in the Results and Discussion chapter.
