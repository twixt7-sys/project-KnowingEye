01 · Introduction

Problem Statement

01 · THE FIELD

Academic integrity

Reviews of AI proctoring name security, privacy, and ethics as the central issues. A review of 154 publications finds cheating detection and student authentication as the main research threads.

02 · AT LCC

Manual proctoring at LCC

The environmental scan (June 1, 2026) found no computer-based exam system with face tracking or identity verification. Suspicious behavior is caught by CCTV or assigned proctors, which is uneven in large exams and adds to proctor workload.

03 · THE TOOLS

Fragmented systems

Existing platforms handle questions and scoring but only monitor passively (webcam recording, screen lock). Nothing analyzes gaze, posture, or facial movement in real time, so review stays manual.

There is no single platform at LCC that both delivers exams and monitors examinee behavior in real time.

Scope and Limitations

IN SCOPE
  • Locale: Legacy College of Compostela, Dagohoy St., Poblacion, Compostela, Davao de Oro.
  • Function: create, administer, and automatically score exams, with behavior monitoring.
  • Data: examinee webcam streams, system-generated behavior logs, and exam interaction logs.
  • Training data: public datasets plus mock exam sessions recorded with consent, used only for training, testing, and evaluation.
LIMITATIONS
  • Institutional web-based exams on desktop or laptop computers with a webcam.
  • Out of scope: mobile app, integration with external institutional databases, biometric hardware, nationwide rollout.
  • No offline mode.
  • Produces behavioral indicators, not accusations of cheating. The administrator makes the final call.

03 · Technical Details

AI Monitoring Pipeline

Capture

Webcam snapshots (~5 fps target), sent as JPEG/base64 over WSS with REST fallback.

Preprocess

OpenCV: resize to ≤640 px, light denoise, histogram normalization.

Detect

YOLOv8n face detector. MediaPipe Face (468 landmarks) and Pose.

Verify

ArcFace (buffalo_l) embeddings compared by cosine distance; checked every 3rd frame on a background thread.

Score

Four indicators normalized to 0–100, combined into an EBI per frame, plus a running session mean.

Escalate

A 60 s sliding window sets the tier; alerts are saved and pushed to the dashboard.

Privacy by default. Frames are analyzed in memory and never written to the database (KE_STORE_FRAMES=False). Face embeddings are kept per session and deleted with it.
Keeps running when parts fail. If the ML libraries are missing, the adapter switches to a deterministic stub, so the monitoring API still responds and exams continue.
03 · Technical Details · Interactive

Exam Behavior Index (EBI)

EBI = (Fp + Fi + Up + Gc) / N
= (100 + 100 + 100 + 100) / 4

The four indicators are formative: each measures a different aspect of behavior, so they need not be correlated. Combining several cues follows proctoring practice.

Good · EBI ≥ 80All indicators are within acceptable limits.
Mid · 50 ≤ EBI < 80One or more indicators deviate moderately. Needs review.
Bad · EBI < 50Significant deviation. Review first.

Why 80 and 50? A published proctoring risk model treats compliance above 75% as no risk and below 50% as maximum risk. We set the upper cut-off at 80, slightly stricter than 75, so a "good" rating is never more lenient than the reference. Classification uses a fixed threshold, as in prior work.

03 · Technical Details · Systems Security Plan

Security and Privacy

AUTHENTICATION

Who you are

  • PBKDF2-salted password hashes
  • JWT: 60-min access token, 7-day refresh token, rotation + blacklist
  • OTP email verification at signup
AUTHORIZATION

What you may do

  • RBAC with per-user permission grants on every API and WebSocket route
  • WebSocket JWT checked by JWTAuthMiddleware
  • Permission changes audited (PermissionChange)
TRANSPORT

How data travels

  • TLS 1.2+ via Nginx, HSTS, secure cookies
  • CORS limited to known frontend origins
  • Rate limits: 60/min anonymous · 1,200/min authenticated
PRIVACY

No raw video stored. Behavior logs are scoped to their session, so examinees see only their own. Face embeddings are deleted with the session to prevent biometric misuse. Uploads are checked for size and type.

INCIDENT RESPONSE

Watch logs for spikes in 401/403/500 errors. If breached: rotate DJANGO_SECRET_KEY, invalidate JWTs, force password resets. Monthly pip audit and npm audit.
