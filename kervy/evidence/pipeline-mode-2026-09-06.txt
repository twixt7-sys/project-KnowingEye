Conclusion: the face/pose pipeline correctly reports "production" once
requirements-cv.txt is installed. Identity verification, even in that
"production" pipeline, silently falls back to the "appearance" backend (a
16x16 grayscale crop compared by cosine distance) because ArcFace
(requirements-identity.txt) is never installed by the documented setup path.
This confirms finding A-5 in 06-qa-findings.md.

Separately, the two [ERROR] lines above show opencv-python-headless's bundled
Haar cascade data files are not resolving at the expected path in this
environment — the Haar fallback path itself is not fully functional here,
though it never had to run since mediapipe loaded successfully.
